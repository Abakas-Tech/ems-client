==================================================================
FRONTEND VALIDATION (MANDATORY)
==================================================================

All frontend validation MUST mirror the backend Joi validation rules.

The backend API documentation is the SINGLE SOURCE OF TRUTH for:
- Required fields
- Data types
- Allowed values
- Min / max limits
- String length constraints
- Enum values
- Date rules

--------------------------------------------------
GENERAL RULES
--------------------------------------------------

1. Every required field in the backend MUST:
   - Have the `required` attribute in the input element
   - Be validated on the frontend before submission

2. Every input MUST be validated for:
   - Correct data type (string, number, date, file, etc.)
   - Allowed range / length / enum values (if applicable)

3. Frontend validation MUST run:
   - BEFORE sending data to the backend
   - Inside a dedicated validation function
   - NOT inside JSX

4. Validation errors MUST:
   - Be user-friendly
   - Clearly explain what is wrong
   - Prevent form submission

--------------------------------------------------
VALIDATION STRUCTURE
--------------------------------------------------

- Create a dedicated validation function for the module
  (e.g., validateTravelRecords(), validateContract(), etc.)
- The function should:
  - Accept the relevant form data object
  - Return an error message string if invalid
  - Return null if valid

--------------------------------------------------
DATA TYPE HANDLING RULES
--------------------------------------------------

- Number fields:
  - Convert to Number before validation
  - Ensure integers / ranges where required
- Date fields:
  - Must be valid ISO dates
  - Apply logical checks (e.g., must be in the past / future)
- Select fields:
  - Must match allowed backend enum values
- File uploads:
  - Validate presence if required
  - Validate file type if specified in backend docs

--------------------------------------------------
REFERENCE IMPLEMENTATION
--------------------------------------------------

Use the Worker Personal Information module as a REFERENCE for:
- Validation approach
- Error handling style
- Data type coercion
- Required attribute usage
- Separation of validation logic from JSX
